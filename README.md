# eximoelle-completions

Коллекция автокомплитов для Zsh.

## Структура

- `plugin.zsh` — подключает `functions/` в `fpath` и регистрирует все `_*`-файлы как комплишены.
- `functions/` — zsh-комплишены.

## Подключение

### znap

```zsh
znap source /path/to/eximoelle-completions
```

### Oh My Zsh

```zsh
ln -s /path/to/eximoelle-completions $ZSH_CUSTOM/plugins/eximoelle-completions
# ~/.zshrc
plugins+=(eximoelle-completions)
```

### Antidote

```zsh
antidote bundle /path/to/eximoelle-completions
```

### Перезагрузка

После установки нужно открыть новую вкладку терминала, чтобы новые комплишены подхватились. Или выполнить в текущем:

```zsh
autoload -Uz compinit && compinit
exec zsh
```

## YC CLI Autocomplete

### Мотивация

YC CLI наряду с `kubectl` или `docker` построен с помощью Cobra: в файлах `completion.bash.inc` и `completion.zsh.inc` есть некоторые сигнатурные признаки этого. 

`completion.bash.inc` — Bash-комплишен, выполняет динамические вызовы скрытой команды `yc __completeNoDesc` через переменную `YC_ACTIVE_HELP=0`. 

`completion.zsh.inc` — обёртка, которая на лету адаптирует Bash-комплишен под Zsh через `bashcompinit`, `sed`-конвертацию и встроенный Bash-скрипт.

Официальная инструкция по установке предлагает пользователям «в индивидуальном порядке» сорсить комплишен в своём `.zshrc` вместо того, чтобы традиционно использовать Zsh'шный `/site-functions`, который подключается любым completion-плагином в любом известном человеко-ориентированном Zsh-фреймворке.

Отказ от общепринятых best practices может быть архитектурным компромиссом кроссплатформенности, но как бы там ни было, предлагаемый взамен комплишен нативно работает под Zsh, не вызывает `yc` в рантайме и имеет приличный, современный, человеко-ориентированный внешний вид, схожий с комплишенами для популярных CLI-инструментов. Поддержаны описания команд, отсутствующие в оригинальных файлах вендора.

Наконец, даже подключение автокомплита для пары утилит с помощью отдельного Zsh-плагина (этого) значительно упрощает поддержку и переносимость конфигурации, когда речь идёт о минималистичных и легкоподдерживаемых решениях вроде модульного Zsh-конфига [eximoelle/zsh-config](https://github.com/eximoelle/zsh-config) или аналогичных. Это действительно лучше, чем добавлять непосредственно в свой `.zshrc` что попало.

Статичность решения является и минусом: при обновлении CLI, при добавлении новых сервисов, комплишен нужно дописывать вручную вместо вендора поверх работы Cobra, хотя делать аналогичный результат силами самой Go-библиотеки технологически более логично, но может удорожить стоимость разработки.

### Структура

- `functions/_yc` — основной файл (`#compdef yc`), работает без вызовов `yc`.
- `_YC_CMDS` — карта путей команд к их подкомандам.
  - Ключи: `yc:service:entity:operation:...` (в некоторых сервисах YC есть ещё «sub-entity» и так далее)
  - Значения: список строк `name` или `name:Описание`.
- `_YC_FLAGS` — карта путей команд к флагам.
  - Глобальные флаги — только в `_YC_FLAGS[global]`.
  - Локальные флаги — только в `_YC_FLAGS[yc:...]`.
  - Формат: `--flag`, `--flag=`, `--flag:Описание`, `--flag=:Описание`.
- Ключи без заполненного описания отображаются списком в несколько колонок, ключи с описанием — по одному на строку.

### Логика выбора

- Путь строится из введённых слов, флаги и их значения пропускаются через `_yc_flag_needs_value`.
- Если текущий токен начинается с `-`, показываются флаги.
- Иначе показываются подкоманды, а если их нет — флаги.

### Известные проблемы

- Нет алиасов команд (в оригинальном `completion.zsh.inc` есть). Для их поддержки нужно расширять логику `_yc()`.
- Ручная поддержка: при добавлении в YC CLI новых поддерживаемых сервисов и веток команд (с выходом новых версий) нужно вручную дописывать их в комплишен.
- При апдейте комплишена описания нужно откуда-то брать (писать вручную или тянуть из help/документации), так как в оригинальном выхлопе Cobra описаний нет.
- Конечно же, лучше всего «лечить» проблему на этапе сборки самого CLI, а не бороться с последствиями с помощью велосипедов на костылях. Тем не менее, копаться в файликах и разбираться с системой автокомплита в Zsh было довольно весело и заняло несколько вечеров.
- Части проекта написаны с использованием средств автоматизации кодирования. Объём статических подсказок по командам и флагам составляет более 2 000 строк и вручную не вычитывался. Описания сервисов и команд могут содержать ошибки и неточности.

### Возможные пути развития

- Реализация инструмента обновления комплишена для автоматического или полуавтоматического добавления в будущем новых веток команд в новых версиях YC CLI.
- Реализация инструмента ручной правки комплишена (например, добавление или исправление описаний отдельных команд). 
- Возможно, хорошим путём решения по соотношению усилий и результата будет написание скилла для агента и сопутствующей Python-оснастки.
